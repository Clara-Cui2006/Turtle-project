# 课堂实时助手（Turtle Project）

一个面向 Windows 本机、单用户、桌面端课堂场景的 localhost 应用。它使用 Edge/Chrome 的浏览器语音识别把中文麦克风语音变成可编辑转写，在本机 SQLite 中保存课程资料，并可通过 DeepSeek 增量整理双版本笔记、自动发现课堂问题和回答问题。

## 功能

- 课程与课堂会话的创建、重命名、删除、历史打开和异常恢复。
- 麦克风中文连续识别，控制器独立于 React 页面生命周期；区分主动暂停、自然结束、可恢复错误与恢复失败，并持续退避恢复。
- 最终转写立即保存；转写可编辑、标记重点、复制和全文检索。
- 最终转写先分类为法律实质内容、课程提醒、闲聊或待判断；原始转写完整保留，只有合格内容进入笔记和自动问答。
- 完整版讲义和提纲版是两份独立的 TipTap 富文本文档，支持标题、中文层级编号、表格、本地图片、链接、引用、查找与自动保存。
- AI 通过经过 Zod 校验的结构化操作回填、移动和重组节点；用户编辑过的节点不会被静默覆盖。
- 自动问答只优先发现法律问题，保存未读、删除和入笔记状态，并可选择具体插入位置。
- 手动问答支持 Enter 发送、Shift+Enter 换行、真实流式显示、停止、编辑、复制、重新生成和归档。
- 问答可加入完整版、提纲版或两个版本，能够移除且不删除原问答。
- SQLite FTS5 对转写、笔记、问答和导入资料做中文子串全文检索。
- 导入 TXT、Markdown、DOCX；导出 DOCX、Markdown、TXT 或完整课堂包。
- 无 API Key 时，除 AI 功能外的课程、转写、编辑、检索、导入和导出均可使用。

## 技术架构

```text
Turtle-project/
├─ apps/
│  ├─ web/          React 19 + Vite + TypeScript
│  └─ server/       Node.js + Express + TypeScript
├─ packages/
│  └─ shared/       Zod 输入契约、共享类型和领域规则
├─ tests/           Vitest 集成与单元测试
├─ package.json     npm workspaces 与统一命令
└─ README.md
```

后端只监听 `127.0.0.1`。前端通过 Vite Proxy 访问后端，不直接访问数据库，也不直接携带 DeepSeek Key 请求公网。SQLite 使用 Node 当前 LTS 自带的 `node:sqlite`，不需要 Visual Studio C++、Python、Docker 或 WSL；FTS5 使用 trigram 分词支持中文子串检索。

## Windows 环境与启动

建议 Windows 10/11、Node.js 24 LTS、npm 11 或更新版本。最低支持版本写在 `package.json`（Node.js 22+），但推荐使用 Node 24 LTS，以获得当前稳定的内置 SQLite 行为。

```powershell
git clone https://github.com/Clara-Cui2006/Turtle-project.git
cd Turtle-project
npm install
npm run dev
```

开发命令会同时启动前后端。项目也提供 PWA 清单，可在受支持的 Edge/Chrome 中安装为独立窗口：

- 网页：<http://localhost:5173>
- 后端：<http://localhost:3001>
- 健康检查：<http://localhost:3001/api/health>

其他命令：

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

如果端口被占用，请先关闭占用 5173 或 3001 的本机进程。后端端口可用 `PORT` 环境变量临时调整，但同时需要更新 Vite Proxy。

## 第一次使用与 DeepSeek

1. 打开右上角“设置”。
2. 在 API Key 输入框填写 Key。Key 不会写入浏览器 localStorage 或 IndexedDB。
3. 保持 Base URL 为 `https://api.deepseek.com`，或填写兼容的 HTTPS 地址。
4. 点击“测试连接”。测试只发送一个极短请求。
5. 成功后点击“保存设置”。

当前官方推荐的默认普通模型是 `deepseek-flash`，深度模型是 `deepseek-v4-pro`；四个任务模型均可在设置中修改。模型名称变化或账号无权使用时，测试连接会显示明确错误。参考 [DeepSeek 官方快速开始](https://api-docs.deepseek.com/) 与 [官方模型价格页](https://api-docs.deepseek.com/quick_start/pricing)。

设置文件位于：

```text
%APPDATA%\TurtleProject\local-settings.json
```

Key 仅由 localhost 后端读取；GET 设置接口只返回是否配置和脱敏值。文件以当前用户创建并尝试设置为仅当前用户读写；Windows 上最终访问范围仍取决于该用户目录的 NTFS ACL。本项目没有实现操作系统凭据保险箱加密，因此不会声称 Key 已加密。不要共享该文件。

点击“清除 API Key”会立即阻止新的 AI 请求。本地课堂功能仍可继续使用。

## 上课流程

1. 左侧点击“新建课程”，填写名称和教师。
2. 选中课程并点击“新建课堂”。
3. 点击顶部“开始转写”，浏览器会申请麦克风权限。
4. 允许后，临时文字用虚线框显示，不写入数据库；最终文字先进入浏览器 IndexedDB 待发队列，再由带幂等键的接口写入 SQLite。
5. 可暂停、继续或结束课堂。已结束课堂必须明确确认“继续本节课堂”才会追加转写。
6. 页面刷新或程序重启后，应用会恢复最近课堂；未正常结束的课堂仍显示为进行中。

麦克风权限被拒绝时，点击浏览器地址栏左侧的网站权限图标，把“麦克风”改为“允许”，然后重新点击开始。系统只捕获麦克风，不捕获系统内部声音、不区分说话人。原始音频默认不保存；只有用户在设置中明确开启后，才会以本地分段文件写入数据目录。

## 内容筛选与实时整理

所有最终转写都保留在原始转写中。语义筛选会结合相邻片段与当前法律主题，把内容分为：

- `substantive_legal`：概念、法条、案例、争议、推理等法律课程实质内容，进入笔记规划和法律问题识别。
- `course_context`：考试、作业、进度等课程管理信息，进入独立的“课程提醒”。
- `small_talk`：寒暄、点名和无关闲聊，默认不进入笔记或自动问答。
- `uncertain`：片段不完整或语义不明，等待后续上下文。

法律教学中的生活事实不会仅凭生活词汇被删除：只要上下文正在解释法律概念、构成要件或案例涵摄，就按实质法律内容处理。用户可在每条转写上手动改分类，手动决定的优先级永久高于 AI 分类。

实时管线只消费最终转写，并先合并过短片段、防抖和去重。完整语义单元触发微更新，用于补定义、观点、案例或待核实内容；主题切换或手动整理触发后台结构整理，用于去重、调整层级、回填前文和形成比较表格。两类任务使用独立队列，不会把每个临时识别结果发送给 DeepSeek。

## 双版本笔记

- 完整版：使用完整句子和层级章节，接近可复习讲义，保留课堂逻辑、时间依据、老师讲述、AI 补充和待核实内容。
- 提纲版：明显更短，使用项目符号，突出层级知识点、法条、案例、易错点和复习问题。

编辑器基于 [TipTap 的 React 集成](https://tiptap.dev/docs/editor/getting-started/install/react)，支持光标自由编辑、撤销/重做、一至四级标题、加粗、斜体、下划线、高亮、列表、引用、分隔线、链接、表格及本地图片粘贴/拖入。图片写入 `%APPDATA%\TurtleProject\assets`，数据库只保存稳定资源 ID；不会静默加载远程图片 URL。

笔记不是不断追加的 Markdown 字符串。`note_documents_v2` 保存文档版本，`note_nodes` 保存稳定节点、父子关系、排序、来源、用户编辑标记和 AI 管理标记。模型只能返回 `insertNode`、`updateNode`、`moveNode`、`mergeNodes`、`convertToTable` 等受支持操作；后端先做 Schema、目标节点、循环、版本和用户内容保护检查，再在事务中生成可撤销修订。老师后来补充案例时，操作会定位原概念节点并插入其下；比较内容可重组为表格。若目标节点已由用户编辑，变更进入建议队列而不是覆盖正文。

完整版与提纲版分别保存、分别编辑：完整版保留讲授逻辑和论证，提纲版压缩为复习层级。中文编号由文档层级和 CSS 计数器生成，不作为易错乱的普通标题文本硬编码。AI 更新采用局部事务，不重新挂载整篇编辑器；正在编辑同一节点时转入建议队列，以保护焦点、选区和输入法状态。

## 自动发现问题与手动提问

自动发现只读取已判定为实质法律内容的最终转写。系统识别概念、制度、法条适用、构成要件、法律效果、案例争点、请求权基础、程序和学理比较等问题；闲聊和纯课堂管理问题不触发。无法确认时保存为“待判断”，由用户决定。

答案提示词按概念、案例、法条、学理和比较问题分别组织，并明确区分课堂原话、导入资料、一般知识、模型推断和待核实内容；不得编造法条、案号或老师观点。系统只取相关片段并限制上下文长度，不会每次发送全部数据库。

新自动问题会在“课堂问答”标签显示持久化未读数量，实际打开后才标记已读。问题卡支持编辑、重答、复制、加入笔记和真实删除。删除已入笔记的问题时，用户可只删卡片或同时移除关联节点。加入笔记会选择完整版、提纲版或两者，推荐现有标题/节点并在确认后插入；数据库用 `qa_note_links` 防止同一问答重复插入。

“手动提问”支持常用快捷问题、流式输出和停止生成。Enter 发送，Shift+Enter 换行。课堂记录里没有答案时，提示词要求模型明确说明。

## 导入、检索与导出

点击“导入”或把文件拖入对话框：

- `.txt` 与 `.md`：UTF-8 文本和标题分块。
- `.docx`：解析普通段落、标题和列表，不执行宏、脚本或嵌入对象。
- `.doc`：不支持，会提示用 Word 另存为 `.docx`。
- 单文件限制 10MB；用 SHA-256 防止同一课程无提示重复导入。

设置中“保留导入原文件”默认关闭，此时只存解析文字和元数据。开启后原文件存入本机数据目录的 `imports` 子目录；删除资料时会一起删除原文件、解析块和全文索引。

顶部“导出”可选择 Word、Markdown、纯文本，以及完整版、提纲版、两版笔记、完整转写、课堂问答或完整课堂包。DOCX 保留一至四级中文标题、正文样式、粗体/斜体/下划线、列表、引用、表格和 PNG/JPEG/GIF 本地图片，并按照当前文档树顺序输出前文补充内容。Word 无法等价表达的高亮或 WebP 等格式会合理降级为正文说明，不丢失文本。导出文件不会包含 API Key、内部路径或调试信息。

## 本地数据、隐私与删除

默认数据目录：

```text
%APPDATA%\TurtleProject
├─ turtle.db
├─ turtle.db-wal / turtle.db-shm（运行时可能存在）
├─ local-settings.json
├─ assets\（编辑器本地图片）
├─ backups\（迁移前和用户手动备份）
├─ recordings\（仅明确开启录音后）
└─ imports\（仅开启保留原文件时）
```

可用非敏感环境变量 `TURTLE_DATA_DIR` 覆盖目录，便于测试。数据库和历史课堂主要保存在本机，但本项目不是完全离线软件：

1. AI 请求会把必要的课堂文字、问题和相关笔记发送给 DeepSeek。
2. 原始音频默认不保存，也不发送给 DeepSeek。
3. Edge/Chrome 语音识别可能使用浏览器厂商的在线服务。
4. 本地文件安全取决于 Windows 用户账户、磁盘和目录权限。

设置页“数据诊断”显示数据库绝对路径、大小、Schema 版本、读写状态、最近写入时间和数据统计；也可创建、列出与选择恢复备份。恢复会先检查 SQLite 完整性、再备份当前数据库，并在应用重启时替换，避免运行中的连接写坏文件。损坏的设置 JSON 会保留为 `.corrupt-*` 文件并显示警告，不会伪装成正常默认值。

旧版升级到 Schema v2 时会先用 SQLite `VACUUM INTO` 创建迁移前备份，再在单个事务中把旧 `note_blocks` 映射为 v2 富文本文档和节点；旧表继续保留。无法可靠映射的内容放入“旧版笔记迁移内容”，迁移失败会整体回滚，不会静默丢弃。不要手工删除 `turtle.db`、WAL 或 SHM 来“修复”升级问题。

彻底删除数据：先结束 `npm run dev`，再删除 `%APPDATA%\TurtleProject`。这会永久删除 Key、所有课程、课堂、转写、笔记、问答和保留的导入文件，请自行先创建备份并导出。

`.gitignore` 已排除 `.env*`、`node_modules`、`dist`、`coverage`、`data`、`uploads`、`recordings`、`exports`、临时目录、数据库、设置、日志和缓存。不要把本地数据目录、真实 Key、课堂转写、笔记、导入资料、导出文件或录音提交到 GitHub。

## 浏览器兼容性与限制

推荐最新版 Microsoft Edge 或 Google Chrome。应用检测 `SpeechRecognition` / `webkitSpeechRecognition`，默认 `zh-CN`、连续识别和临时结果。Firefox 通常不提供该接口；不支持时，本地课程、手写笔记、导入、检索和导出仍可使用。

转写控制器是模块级单例，不因页面滚动、编辑笔记、切换右侧标签或普通 React 重渲染而销毁。`visibilitychange`、`blur` 和滚动不会主动停止识别；回到前台会做健康检查，意外 `end`、`no-speech` 和暂时网络错误会退避重启。诊断面板记录状态事件与时间，但不记录音频或 API Key。课堂进行中会尽力申请 Screen Wake Lock；它只能防止屏幕休眠，不能保证浏览器厂商的语音服务永久运行。

纯浏览器 `SpeechRecognition` 无法保证在所有 Windows、Edge/Chrome 版本、标签后台或最小化状态下永久工作。操作系统节能、浏览器节流和厂商在线语音服务都可能终止会话；本项目能检测并恢复应用层可恢复中断，但不能绕过这些平台限制。PWA 独立窗口降低误关普通标签的概率，也不构成永久后台承诺。

当前限制：Windows localhost、单用户、桌面端优先；不提供公网部署、账号登录、云同步、手机远程访问、系统内部声音捕获、精确说话人区分、完全离线识别、PDF 或图片 OCR。

未来替换本地 Whisper 时，在 `apps/web/src/transcriptionController.ts` 注入实现 `BrowserTranscriptionProvider` 契约的持续音频流 Provider 即可，保持开始、暂停、停止、临时/最终结果和状态事件接口；数据库与上层 UI 不需要改写。本版本没有安装大型 Whisper 模型，也不会默认保存原始录音。

## 界面与乌龟角色

桌面主区固定在视口剩余高度，左侧课程、中间转写和右侧笔记/问答各自设置 `min-height: 0` 与独立 `overflow-y: auto`；正文增长不会继续撑高 `body`。用户向上查看历史转写时不会被强制拉到底部，新内容通过“有新内容”按钮提示。

左上角使用仓库内的透明素材 `apps/web/src/assets/turtle-normal.png` 与 `turtle-angry.png`。点击或用 Enter/Space 触发后短暂切换生气版并抖动，结束后恢复；快速点击有锁，动画不发声、不请求 API、不影响转写。启用 `prefers-reduced-motion` 时仅切图，不执行位移动画。

## 常见问题

| 问题 | 处理方法 |
|---|---|
| 麦克风权限被拒绝 | 在地址栏网站权限中允许 localhost 使用麦克风，再重新开始。 |
| 浏览器不支持语音识别 | 使用最新版 Edge/Chrome；仍可手动记录、导入和导出。 |
| DeepSeek Key 无效 | 在设置重新填写，点击测试连接；完整 Key 不会从读取接口返回。 |
| 模型不可用 | 把任务模型改为账号当前可用的官方模型名并重新测试。 |
| 额度不足 | 到 DeepSeek 平台检查余额或配额，本地保存不受影响。 |
| 请求过于频繁 | 稍后重试；后端会有限重试且不同任务使用独立队列。 |
| 网络异常 | 检查代理、防火墙与 `https://api.deepseek.com`；待处理转写不会丢失。 |
| Word 导入失败 | 确认是有效 `.docx` 且小于 10MB；旧 `.doc` 请另存为 `.docx`。 |
| 数据库无法打开 | 检查 `%APPDATA%\TurtleProject` 权限、磁盘空间和是否被其他程序锁定；不要删除 WAL 文件来“修复”。 |
| 端口被占用 | 关闭占用 5173/3001 的程序后重启。 |

## 测试说明

自动化测试不会访问真实 DeepSeek，也不会消耗 API 额度。当前 22 项测试覆盖内容分类和人工优先级、闲聊保留与过滤、结构化插入/更新/移动/合并/表格、用户编辑保护、撤销、重启持久化、旧数据迁移、设置损坏诊断、问答未读/删除/定点插入与幂等、语音自然结束恢复和主动暂停不恢复、本地录音与个人数据备份，以及含多级标题、表格、图片的 Word 导出。

发布前执行：

```powershell
npm install
npm run typecheck
npm run lint
npm run test
npm run build
npm run dev
```

自动测试能验证生命周期状态机和数据完整性，不能替代在目标 Windows 机器上使用真实麦克风进行至少十分钟的 Edge/Chrome 前台、切换标签、切换程序和最小化测试。验收时请打开默认折叠的“转写诊断”，以事件时间线判断是应用恢复失败还是浏览器服务被平台终止。
